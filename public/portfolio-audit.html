Counting rules

Cross-repository audit findings

Name and description mismatches

  • technical-writing-workflows: repository Description is “github”, while README describes a Docs-as-Code CI pipeline.
  • api-docs-portfolio: generic Description and two-line README; it is not a complete portfolio like V2.
  • global11-demo-data-platform: repository Description mentions SQLite data access, but README excludes the Deshifrator SQLite layer.
  • adp201p4-hardware-spec: Homepage metadata points to github.com, not its GitHub Pages site.
  • ekatmoz88-alt.github.io: repository Description is “technical-writing-portfolio”, although its contents are the portfolio website hub.
  • icao-mrtd-documentation: repository name promises documentation, but current content is only a title line.

Content overlap and boundaries

  • technical-writing-portfolio and api-docs-portfolio-v2 both contain Orders API portfolio material. Their distinct scope should remain explicit; do not present them as two unrelated production APIs.
  • adp201p4-hardware-spec-editable is a working copy of adp201p4-hardware-spec, not a second case study.
  • territory-docs complements ppo-territory-archive; passport and migration accounting are PPO Territory domains, not another system.
  • PPO Territory, ARM Descriptor, Deshifrator and UMMS remain separate system boundaries. A shared portfolio hub is navigation, not proof of a common runtime.
  • desktop and js.org are forks; they must not be counted as original portfolio projects.
Evidence limitation: repository metadata fields (Description, Homepage and GitHub Topics) are not writable through the currently connected GitHub actions. This audit identifies exact corrections; repository README/source files can be edited, but metadata changes must be applied in GitHub repository settings.
